# VeloProve Examples & Recipes

Practical, concise recipes for common testing, verification, and autonomous workflows with VeloProve.

---

## Recipe 1: Verify-first agent loop

Prefer **`veloprove verify`** (or `vp.verify`) for change-aware QA. Manual steps below are the expanded form of the same engine path — see packaged [`AGENTS.md`](../AGENTS.md).

```bash
# Teach the agent once (optional but recommended)
npx veloprove teach-ai --force --mcp

# One-shot: impact → targeted tests → diagnose → heal TEST_BUG → release gate
npx veloprove verify --json --ci

# Or expand manually when debugging:
npx veloprove inspect
npx veloprove changed
npx veloprove test --scope changed
npx veloprove diagnose
npx veloprove heal          # locators in @veloprove-generated / healable tests only
# vp.suggestFix / auto-fix = guidance / REVIEW_REQUIRED — not guaranteed patches
npx veloprove release --ci
```

## 🌐 Recipe 3: Next.js App Router E2E Testing

### Playwright Test Generated by VeloProve:
```typescript
import { test, expect } from '@playwright/test';

test.describe('Feature: Checkout Flow', () => {
  test('TC-CHECKOUT-001: Completes checkout with valid cart items', async ({ page }) => {
    await page.goto('/cart');
    await page.getByRole('button', { name: /checkout/i }).click();

    await expect(page).toHaveURL(/\/checkout/);
    await page.getByLabel(/shipping address/i).fill('123 Main St');
    await page.getByRole('button', { name: /place order/i }).click();

    await expect(page.getByRole('heading', { name: /order confirmed/i })).toBeVisible();
  });
});
```

## 🚀 Recipe 4: Express REST API with Dynamic Variables & Auto-Auth

### Native VeloProve API Test Spec:
```typescript
import { NativeApiRunner } from '@engnadia/veloprove';

const runner = new NativeApiRunner('http://localhost:3000');

const result = await runner.executeChain([
  {
    id: 'AUTH-LOGIN',
    name: 'Login as Admin',
    method: 'POST',
    path: '/api/auth/login',
    body: { email: 'admin@example.com', password: 'secretpassword' },
    expectedStatus: 200,
    extractVars: { token: 'token', adminId: 'user.id' }
  },
  {
    id: 'CREATE-PRODUCT',
    name: 'Create New Inventory Product',
    method: 'POST',
    path: '/api/products',
    headers: { Authorization: 'Bearer {{token}}' },
    body: { name: 'Widget-{{$uuid}}', price: 29.99 },
    expectedStatus: 201,
    extractVars: { productId: 'id' }
  },
  {
    id: 'DELETE-PRODUCT',
    name: 'Teardown Cleanup Product',
    method: 'DELETE',
    path: '/api/products/{{productId}}',
    headers: { Authorization: 'Bearer {{token}}' },
    expectedStatus: 200
  }
]);
```

## 🚦 Recipe 10: CI/CD Quality Gate (GitHub Actions)

Generate autonomous CI quality gate:
```bash
npx veloprove setup-ci
```

In your CI pipeline:
```yaml
- name: Run VeloProve Autonomous Release Gate
  run: npx veloprove release --ci
```
Exits with status code `0` on `READY` / `READY_WITH_WARNINGS` and status code `1` on `NOT_READY` with actionable blocking recommendations.

## 🧩 Recipe 11: Node.js Built-in `node:test` Projects

When `package.json` uses `"test": "node --test"` (or the stack detects `node:test`):

```bash
npx veloprove init -y
npx veloprove plan
npx veloprove generate   # emits .test.js with node:test + node:assert/strict
npx veloprove verify --ci
```

Generated unit smoke looks like:

```javascript
import { describe, it } from 'node:test';
import assert from 'node:assert/strict';

describe('Feature: Math', () => {
  it('REQ-1: Sample case', () => {
    assert.equal(true, true);
  });
});
```

Doctor, verify, and the NodeTest adapter treat `node:test` as a first-class runner alongside Vitest/Jest/Playwright.
